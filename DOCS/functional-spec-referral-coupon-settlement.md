# 지구별 웹프로젝트 기능정의서

## 추천인 코드 · 쿠폰 · 파트너 수수료 정산

- 문서 상태: 확정
- 버전: 1.0
- 기준일: 2026-09-12
- 연계 Figma: `B2B2C 매장가구 인테리어 플랫폼 - A안 Wireframe`

## 1. 범위

본 정의서는 리세일파트너 추천인 코드, 파트너 쿠폰 캠페인, 회원 쿠폰, 구매·렌탈 수수료, 정산·분쟁·세금계산서 및 파트너 자격 관리를 다룬다.

## 2. 역할

| 역할 | 주요 권한 |
|---|---|
| 고객회원 | 가입 전 추천코드 입력·변경, 쿠폰 등록·선택·사용, 본인 이력 조회 |
| 파트너 담당자 | 자신의 추천코드·집계 실적·정산서 조회, 이의신청 |
| 운영관리자 | 일반 코드·캠페인 운영, 미래 시점 귀속 변경, 정산 검토 |
| 슈퍼관리자 | 권한관리, 소급 변경, 긴급 중지, 예외 복원, 정산 재계산·회수 승인 |

## 3. 추천인 코드

### RF-01 코드 규칙

- 형식: `RS-{파트너 코드}-{담당자 코드}`
- 대문자 canonical code로 저장하며 전역 중복을 금지한다.
- 입력 시 대소문자를 구분하지 않고 앞뒤 공백을 제거한다.
- 기존 코드는 신규 형식으로 전환하고 과거 값은 alias로 보존한다.

### RF-02 가입 검증

- 상태: `유효`, `존재하지 않음`, `중지`, `만료`.
- 유효하면 파트너명과 담당자를 표시한다.
- 가입 전 수정·재검증 가능하며 입력 변경 시 이전 검증은 무효화한다.
- 가입 완료 직전 서버에서 최종 재검증한다.
- 가입 후 고객 직접 변경은 불가하다.

### RF-03 귀속 우선순위

- 추천 링크 코드를 기본 적용한다.
- 사용자가 다른 유효한 코드를 직접 확인하면 마지막 직접 확인 코드를 우선한다.
- 잘못된 직접 입력은 유효한 링크 코드를 덮어쓰지 않는다.
- 링크·입력·최종 코드를 모두 로그에 저장한다.
- UTM은 분석용이며 추천인 귀속을 바꾸지 않는다.

### RF-04 최초·현재 귀속

- 최초 추천코드·파트너 귀속은 영구 보존한다.
- 운영관리자는 현재 귀속 파트너를 변경할 수 있다.
- 변경은 `effective_from` 이후 신규 거래에만 적용한다.
- 기존 거래와 완료 정산은 유지한다.
- 소급 변경은 슈퍼관리자 승인과 정산 재계산이 필요하다.
- 거래에는 partner/referrer/commission rule snapshot을 저장한다.

### RF-05 개인정보

- 가입 시 파트너 귀속과 수수료 산정 목적을 고지한다.
- 파트너 기본 화면에는 집계 실적과 정산정보만 제공한다.
- 상담에 필요한 개인정보만 담당자에게 제한 제공한다.
- 개인정보 조회·내보내기는 권한과 접근로그를 요구한다.

## 4. 쿠폰

### CP-01 데이터 구조

- 파트너 공용 코드는 Campaign Coupon Code 마스터다.
- 고객이 등록하면 회원별 Member Coupon을 발급한다.
- 동일 회원은 동일 캠페인에서 기본 1회만 발급받는다.
- 캠페인 파트너는 성과 집계에만 사용하고 추천인 귀속을 바꾸지 않는다.

### CP-02 상태

`DRAFT → ISSUED → RESERVED → USED`

예외 상태: `SUSPENDED`, `EXPIRED`, `REVOKED`.

- 결제 실패·주문 미완료·예약시간 초과: `RESERVED → ISSUED`.
- 예약 해제 시 기간 만료: `EXPIRED`.
- 삭제는 업무 상태가 아니라 감사기록이 남는 soft-delete 표시다.

### CP-03 적용 범위

- 전체 상품·카테고리·브랜드·지정 상품을 지원한다.
- 구매·렌탈 적용 여부를 각각 설정한다.
- 배송비·설치비·보증금·부대비용은 제외한다.
- 최소금액은 적용 대상 상품의 할인 전 금액으로 계산한다.
- 정률 쿠폰에는 최대 할인금액을 필수 설정한다.
- 주문당 쿠폰 1개만 허용한다.
- 최대 할인 쿠폰을 추천하되 최종 선택은 고객이 한다.

### CP-04 결제 검증

서버 검증 순서:

1. 상태
2. 유효기간
3. 회원 소유권
4. 구매·렌탈 및 상품 적용 범위
5. 최소 주문금액
6. 제외·중복 할인
7. 캠페인·회원 사용 한도
8. 할인액과 상품별 배분
9. 트랜잭션 내 원자적 `RESERVED` 전환

### CP-05 유효기간

- 고객 기준은 `Asia/Seoul`이다.
- 만료일 23:59:59까지 유효하다.
- 발급 후 N일은 발급일을 1일차로 계산한다.
- 데이터베이스는 UTC로 저장한다.
- 예약시간 내 결제가 완료되면 예약 중 만료되어도 사용을 인정한다.

### CP-06 캠페인 중지

- 일반 중지: 신규 등록·발급만 차단하고 기존 회원 쿠폰은 유지한다.
- 긴급 중지: 슈퍼관리자 승인으로 기존 발급 쿠폰까지 `SUSPENDED`.
- 예약 중 쿠폰은 결제 결과 후 상태를 결정한다.

### CP-07 취소·반품

- 전액 취소: 유효한 원 쿠폰을 `ISSUED`로 복원한다.
- 원 쿠폰이 만료됐다면 동일 혜택의 보상 쿠폰을 신규 발급한다.
- 부분 취소·반품: 주문 시 상품별로 비례 배분한 실결제액만 환불한다.
- 부분 취소 시 원 쿠폰은 `USED`를 유지한다.
- 부분 취소 후 잔존 주문금액이 최소금액보다 작아져도 이미 확정된 할인액을 추가 회수하지 않는다.

## 5. 수수료

### ST-01 구매

`수수료 기준매출 = 상품 판매가 - 쿠폰 할인 - 취소·환불액`

부가세·배송비·설치비·보증금은 제외한다.

### ST-02 렌탈

- `예상 총수수료 = 수수료 대상 총 약정액 × 계약 수수료율`.
- 계약 체결·설치 인수·첫 회차 납부 완료 후 50%를 선 지급한다.
- 잔여 50%는 정상 또는 위약 종료 시 최종 정산한다.
- 미수·위약·감액은 인정 약정액을 재계산해 잔여 수수료에서 조정한다.
- 부족액은 마이너스 수수료로 등록한다.

### ST-03 마이너스 수수료

- 다음 정산에서 오래된 건부터 우선 공제한다.
- 계약 종료 또는 3개월간 상계 불가 시 반환 청구로 전환한다.
- 상태: 상계대기, 일부상계, 반환청구, 입금확인, 연체, 회수완료, 회수불가.

### ST-04 일정

- 매월 말일 마감.
- 익월 5영업일까지 정산서 제공.
- 수령일부터 5영업일 이의신청.
- 이의신청 기간 내 접수된 분쟁이 없으면 정산서를 자동 확정한다.
- 익월 27일 지급, 비영업일이면 직전 영업일.
- 세금계산서는 지급일 3영업일 전까지 발행한다.
- 세금계산서 미발행·오류 시 해당 파트너의 해당 월 지급만 보류한다.
- 세금계산서 문제가 해소되면 확인 후 5영업일 이내 별도 지급한다.

### ST-05 분쟁

- 분쟁 개별 거래만 `HOLD`하고 다른 정상 수수료는 지급한다.
- 파트너 승소: 해결 승인 후 5영업일 이내 별도 지급.
- 미지급 확정: 보류액 취소.
- 기지급 환수: 잔여 수수료 공제 후 부족액을 마이너스 수수료로 등록한다.

## 6. 파트너

### PT-01 자격·등록

- 유효한 법인 또는 개인사업자만 허용한다.
- 필수: 사업자등록증, 법인등기 또는 대표자 확인, 통장사본, 정산담당자, 계약서, 관련 동의.
- 서류·사업자·계좌·계약 검증 후 `ACTIVE` 처리한다.

### PT-02 재검증

- 사업자 상태와 계좌를 매년 1회 검증한다.
- 주요 정보 변경 시 즉시 재검증한다.
- 완료 전 신규 수수료 지급만 보류한다.

### PT-03 계약 종료

- 종료 후 신규 귀속·코드·캠페인 발급을 중지한다.
- 종료 전 확정 구매·렌탈 계약은 거래 종료까지 정산한다.
- 종료 후 신규 거래에는 과거 파트너 수수료를 지급하지 않는다.
- 과거 귀속은 이력으로만 보존한다.

## 7. 관리자 화면 요구사항

- 최초 귀속, 현재 귀속, 적용 시작일, 변경 이력
- 코드 상태와 검증 로그
- 캠페인 마스터와 회원 쿠폰 분리 조회
- 쿠폰 상태별 지표와 조회 기간·기준시각 표시
- 렌탈 예상수수료, 선지급, 미수, 잔여, 공제, 마이너스 원장
- 정상 지급액과 분쟁 보류액 분리
- 세금계산서·파트너 재검증 보류 사유
- 요청자와 승인자가 동일하지 않은 승인 워크플로

## 8. 필수 고객 화면 상태

- 추천코드: 유효, 없음, 중지, 만료, 재검증 필요, 네트워크 오류
- 쿠폰 등록: 성공, 이미 등록, 유효하지 않음, 만료, 중지, 회원·채널 불일치
- 결제: 적용 가능, 최소금액 미달, 제외상품, 예약 중, 만료, 동시사용 실패
- 취소: 원 쿠폰 복원, 보상 쿠폰 발급, 부분 취소 배분 결과

## 9. 공통 감사 필드

`event_id`, `entity_type`, `entity_id`, `action`, `before`, `after`, `reason`, `requested_by`, `approved_by`, `occurred_at`, `source_ip`, `correlation_id`.

모든 금액 조정과 상태 전이는 원 거래 ID 및 멱등키를 사용해 중복 처리를 방지한다.
